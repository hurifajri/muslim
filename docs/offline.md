# Offline

- Service worker aktif pada production build. Buka aplikasi dan halaman bacaan sekali saat online agar halaman serta asetnya tersimpan. Halaman yang belum dikunjungi masih membutuhkan koneksi.
- Dua belas latar poster WebP diprecache bersama aset statis, masing-masing di bawah 2 MiB; total anggaran latar 4 MiB. Poster memakai URL aset asli agar pilihan latar tidak bergantung pada cache transformasi gambar Next.
- Endpoint `/api/prayer-times` dan `/api/location/*` menggunakan jaringan tanpa fallback service worker, begitu pula URL penyedia lama selama transisi. Jadwal memiliki cache aplikasi tervalidasi: maksimal 12 respons, terpisah menurut lokasi, metode, penyesuaian kalender dan tanggal. Jika permintaan gagal, data tersimpan diberi tanggal dan penanda; data lama tidak digunakan untuk countdown hari ini.
- Proxy Aladhan menyimpan maksimal 256 jadwal selama satu jam per proses server. Ini berbeda dari cache offline perangkat. Tanggal dan waktu pengambilan asli dipertahankan saat respons server disimpan ke perangkat; cache perangkat lama tidak dihapus atau diubah formatnya.
- Pencarian lokasi memerlukan koneksi dan hanya berjalan setelah Cari/Enter; fokus tab dan reconnect tidak mengirim ulang pencarian. Endpoint lokasi internal memakai NetworkOnly; cache hasil dikelola oleh server dan query aplikasi. Jadwal yang belum tersimpan memerlukan koneksi. Tersambung kembali memperbarui jadwal, tanpa me-reload halaman.
- Progres, favorit dan pengaturan berada di penyimpanan browser. Tab pada origin yang sama memperbarui data saat menerima perubahan storage, kembali fokus, atau dipulihkan. Mutasi membaca data terbaru di dalam Web Lock agar penulisan antar-tab tidak saling menimpa. Browser tanpa Web Locks tetap menyegarkan data dan mengantre mutasi dalam tab, tetapi tidak menjamin penulisan bersamaan antar-tab.
- Menghapus data situs juga menghapus progres, favorit dan pengaturan. Jika penyimpanan diblokir atau penuh, perubahan tetap bisa dipakai di memori selama halaman terbuka. Satu toast memberi peringatan; sesi dan pengaturan menampilkan status sementara. Perubahan sementara hilang saat reload/halaman ditutup, tidak disinkronkan antar-tab, dan tidak otomatis ditulis setelah storage pulih agar tidak menimpa data dari tab lain.

Verifikasi dengan production build (`pnpm build`, `pnpm start`), kunjungi halaman, tunggu service worker aktif, lalu gunakan mode offline pada browser. Mode development memakai kebijakan jaringan berbeda.
